# Using AI Assistants with the e-INFRA CZ Design System

> Last verified against `@e-infra/design-system` **v0.2.0**.

If you use an AI coding assistant — Claude Code, Cursor, GitHub Copilot, Roo Code, or similar — this guide shows you how to configure it to understand the design system correctly. Without this setup, assistants will not use the design system properly: they guess component names, hard-code colors, and invent layouts.

With the skill below in place, the assistant will generate correct component imports, use the token system properly, apply responsive spacing, follow the layout composition rules, and avoid the most common mistakes automatically.

---

## What the skill does

You add one instruction file to your project that tells the assistant:

- Which components exist in `@e-infra/design-system` (and which don't, so it stops hallucinating them)
- How the color token system and the branding themes work
- How spacing scales across breakpoints
- Which `variant`, `size` and other prop values each component accepts
- How to compose layouts with the header, sidebar, footer, and content components
- How to build chat interfaces from the chat components
- What the surface elevation hierarchy is and how to apply it

You do this once per project. From then on, every chat session and inline completion is grounded in the actual library, not the assistant's best guess.

Every tool below uses the same content: the [skill](#the-skill) at the end of this page. Only the file location differs.

### Claude Code

Paste the skill into `CLAUDE.md` at your project root. Claude Code loads it into every session.

```
your-project/
└── CLAUDE.md
```

Alternatively, add it as a skill so it loads only when UI work comes up. Create `.claude/skills/e-infra-design-system/SKILL.md` and start the file with:

```markdown
---
name: e-infra-design-system
description: Rules for building UI with @e-infra/design-system — components, tokens, spacing, and layouts. Use for any React UI work in this project.
---
```

## The skill

Copy everything in the block below.

````markdown
## e-INFRA CZ Design System

This project uses `@e-infra/design-system` (v0.2.0). Follow these rules for all UI code.

### Setup

```bash
bun add @e-infra/design-system
```

Requires React 18 or 19 and Tailwind CSS v4 (v3 is not supported). The other peer dependencies (Radix UI packages, `class-variance-authority`, `clsx`, `tailwind-merge`, `sonner`, `react-hook-form`, `react-day-picker`, `cmdk`, `embla-carousel-react`, `react-resizable-panels`, `recharts`) are listed in the package's `package.json`; install any your package manager does not install automatically. Icons come from `lucide-react`, which ships with the library.

```css
/* Global CSS file, right after the Tailwind import */
@import "tailwindcss";
@import "@e-infra/design-system/setup.css";
@source "../node_modules/@e-infra/design-system/dist";
```

`setup.css` is required — without it, no token class (`bg-surface`, `text-primary`, …) resolves to any value.

Package exports:
- `@e-infra/design-system` — components, utilities (`cn`), hooks
- `@e-infra/design-system/setup.css` — required base CSS and default e-INFRA CZ theme
- `@e-infra/design-system/eosc_setup.css` — EOSC theme (optional, on top of `setup.css`)
- `@e-infra/design-system/elter_setup.css` — eLTER theme (optional, on top of `setup.css`)
- `@e-infra/design-system/custom_setup.css` — 3-color custom theme generator (optional, on top of `setup.css`)

Use `cn(...)` from the package to merge class names (`clsx` + `tailwind-merge`).

### Dark mode and themes

Dark mode is the `.dark` class on `<html>`. There is no React provider — it is a pure CSS class strategy. All tokens switch automatically.

```tsx
document.documentElement.classList.toggle('dark')
// or: <html className={isDark ? 'dark' : ''}>
```

Never write `dark:` overrides on semantic token classes — they are already theme-aware.

Branding themes are switched with `data-theme` on the **same element** as `.dark`:

```tsx
<html data-theme="eosc" className="dark">   {/* "eosc" | "elter" | "custom"; omit for the default theme */}
```

- EOSC needs the app to load Roboto and set `--font-roboto`; eLTER needs Montserrat and `--font-montserrat` (headings only). The library ships no font files.
- Custom theme: import `custom_setup.css`, then define three colors — everything else (ramps, foregrounds, dark mode) is derived:

```css
[data-theme="custom"] {
  --brand-primary:   #6d28d9;
  --brand-secondary: #db2777;
  --brand-tertiary:  #0d9488;
}
```

### Color tokens — never use raw hex or generic Tailwind colors

**Surfaces — use in order, never skip or reverse:**

| Token | Role | Light | Dark |
|---|---|---|---|
| `bg-background` | Page canvas, app shell | `#f4f5f9` | `#0f0e14` |
| `bg-surface` | Cards, inputs, sidebar | `#eaebf1` | `#191820` |
| `bg-surface-raised` | Popovers, modals, dropdowns | `#dddee6` | `#242330` |

Text: `text-text` (body) · `text-text-muted` (secondary / helper) · `text-text-heading` (headings)
Border: `border-border` (strokes) · `border-border-focus` (focus ring)

**Brand and semantic tokens + ramps:**

| Token | Filled | Ramp |
|---|---|---|
| `primary` | `bg-primary text-primary-foreground` | `primary-50` … `primary-950` |
| `secondary` | `bg-secondary text-secondary-foreground` | `secondary-50` … `secondary-950` |
| `tertiary` | `bg-tertiary text-tertiary-foreground` | `tertiary-50` … `tertiary-950` |
| `info` | `bg-info text-info-foreground` | `info-50` … `info-950` |
| `success` | `bg-success text-success-foreground` | `success-50` … `success-950` |
| `warning` | `bg-warning text-warning-foreground` | `warning-50` … `warning-950` |
| `error` | `bg-error text-error-foreground` | `error-50` … `error-950` |

Ramps: `50–200` subtle tints · `300–600` interactive / hover states · `700–950` strong accents and text on light backgrounds.
Neutral: `base-50` … `base-950` (theme-independent cool grey). Charts: `chart-1` … `chart-7`.

Always write token classes as complete literal strings. Tailwind only generates classes it finds in source, so `` `bg-${status}-100` `` produces no CSS — map values to full class names instead.

### Spacing — always responsive for layout containers

8px base grid. Breakpoints: phone (default) · `md:` 768px · `lg:` 1024px · `xl:` 1280px · `3xl:` 1920px.

| Token | Phone | Tablet `md:` | Desktop `lg:` | XL `xl:` | Role |
|---|---|---|---|---|---|
| `token-space-1` | `p-2` | `p-3` | `p-4` | `p-6` | Inner padding |
| `token-space-2` | `p-4` | `p-6` | `p-8` | `p-12` | Section gutter |
| `token-space-3` | `p-6` | `p-8` | `p-12` | `p-16` | Card padding |
| `token-space-4` | `p-8` | `p-12` | `p-16` | `p-24` | Section rhythm |

The `token-space-*` names are conceptual — apply them as the responsive Tailwind class stacks above (e.g. card padding = `p-6 md:p-8 lg:p-12`).

Page margin: `px-4 md:px-6 lg:px-8 xl:px-16`
Grid: `grid-cols-4 md:grid-cols-8 lg:grid-cols-12 gap-4 md:gap-6 lg:gap-8`

Library components already carry their own padding (e.g. `Card` uses `py-6` / `px-6`). Apply responsive spacing to your own layout containers; don't override component padding unless the design calls for it.

Extra utilities from `setup.css`: `transition-default`, `transition-default-colors`, `transition-default-opacity`, `transition-default-transform`, `duration-default`, `ease-default`, `scrollbar-gutter-stable`, `animate-typing-dot`, `animate-slideUp`.

### Component API cheat-sheet — only use these prop values

Default value first. Values not listed here do not exist — e.g. there is no `primary` or `destructive` Button variant (use `default` and `error`), and Badge has no `success` / `warning` / `info` variant (use literal ramp classes such as `className="bg-success-100 text-success-900"`).

| Component | Prop | Values |
|---|---|---|
| `Button` | `variant` | `default` · `secondary` · `tertiary` · `info` · `success` · `warning` · `error` · `outline` · `ghost` · `link` · `animated-underline` |
| `Button` | `size` | `default` · `sm` · `lg` · `icon` · `icon-sm` · `icon-lg` |
| `Button` | `asChild` | Renders the child (e.g. a router link) with button styles |
| `AlertDialogAction` / `AlertDialogCancel` | `variant`, `size` | Same as `Button`. Action defaults to `default`, Cancel to `outline` |
| `Badge` | `variant` | `default` · `secondary` · `error` · `outline` |
| `Alert` | `variant` | `default` · `success` · `warning` · `error` |
| `Card` | `variant` | `default` (`bg-surface`) · `primary` · `secondary` · `tertiary` · `gradient` |
| `Card` | `animation` | `static` · `translate` (lifts on hover) |
| `CardMedia` | `aspectRatio` | `video` · `square` · `auto`. Renders an `<img>` (pass `src`, `alt`) or `asChild` for your own image component |
| `Toggle` / `ToggleGroup` | `variant`, `size` | `default` · `outline`; `default` · `sm` · `lg`. `ToggleGroup` also takes `spacing` (number, default `0`) |
| `SelectTrigger` | `size` | `default` · `sm` |
| `SheetContent` | `side` | `right` · `top` · `bottom` · `left` |
| `DropdownMenuItem` / `ContextMenuItem` / `MenubarItem` | `variant`, `inset` | `default` · `error` (destructive actions); `inset` aligns items without an icon |
| `Carousel` | `orientation` | `horizontal` · `vertical` |
| `Searchbar` | `size` | `md` · `sm` · `lg`. Also `onValueChange`, `onClear`, `clearable` (`true`), `loading`, `shortcut` (e.g. `"⌘ K"`) |
| `Bubble` | `variant` | `default` · `secondary` · `muted` · `tinted` · `outline` · `ghost` · `error` |
| `Bubble` | `align` | `start` · `end` |
| `BubbleReactions` | `side`, `align` | `bottom` · `top`; `end` · `start` |
| `Message` | `align` | `start` (other party) · `end` (the current user) |
| `MessageTimestamp` | `placement`, `reveal` | `inline` · `beside`; `hover` · `always`. Pass the ISO value as `dateTime` and the label as children |
| `MessageInput` | `status` | `ready` · `submitted` · `streaming` |
| `Stepper` | `totalSteps` | Number of steps. **Always pass it** (`totalSteps={steps.length}`) — when omitted it is inferred from `Stepper`'s direct children, which are usually `StepperHeader`, `StepperContent` and `StepperFooter`, not your steps |
| `Stepper` | `initialStep`, `step`, `onStepChange` | 0-based. `initialStep` for uncontrolled; `step` + `onStepChange` for controlled |
| `StepperHeader` | `steps`, `showNavigation` | `{ label, description?, icon? }[]`; `true` (previous/next arrows in the header) |
| `StepperFooter` | `showDefaultButtons`, labels, `onFinish` | `true`; `nextLabel` / `previousLabel` / `finishLabel`. Pass children to replace the buttons (use `useStepper()` inside) |
| `HeaderContent` / `FooterContent` / `FooterMeta` | `container` | `true` (centered max-width) · `false` (full width) |
| `Sidebar` | `fullHeight` | `false` (below the header) · `true` (beside the header) |
| `NavItem` | `isActive`, `asChild` | Active styling; render the child as the anchor |
| `CollapsibleGroup` | `title`, `defaultOpen` | Required string; `false` |

`badgeVariants`, `buttonVariants`, `toggleVariants`, `bubbleVariants`, `bubbleReactionsVariants` and `messageTimestampVariants` return the class string for the same values — use them to style a non-component element, e.g. `<a className={buttonVariants({ variant: 'outline' })}>`.

### Navigation rule

- **Header-only layout**: navigation goes in `HeaderLeft` using `NavigationMenu` primitives.
- **Sidebar layout**: the sidebar owns ALL primary navigation via `NavItem` and `CollapsibleGroup`. The header contains only utility controls — search, notifications, user avatar. Never put primary navigation in both places.
- **Footer**: secondary links only (privacy, docs, contact) via `FooterNavLink` or ghost `Button`s — never a copy of the primary navigation.

### Router links

`NavigationMenuLink`, `NavItem` and `Button` render a plain `<a>`/`<button>`. With a client-side router (Next.js, React Router, TanStack Router, …), pass `asChild` and put the router's link inside, so the design system supplies the styling and the router handles navigation. Never nest a `Button` inside a link (or a link inside a `Button`) — that renders invalid `<a><button>` markup.

```tsx
import Link from 'next/link' // or: import { Link } from 'react-router-dom'

// ✅ Internal navigation — client-side, no reload
<NavigationMenuLink asChild><Link href="/dashboard">Dashboard</Link></NavigationMenuLink>
<NavItem asChild isActive={pathname === '/docs'}><Link href="/docs">Docs</Link></NavItem>
<Button asChild><Link href="/settings">Settings</Link></Button>

// ❌ Full page reload
<NavigationMenuLink href="/dashboard">Dashboard</NavigationMenuLink>

// ❌ Invalid nesting
<Link href="/settings"><Button>Settings</Button></Link>
```

External URLs and `mailto:` links may use `href` directly. The plain `href` examples below are framework-agnostic — swap in `asChild` + your router's link when one is available.

### Page layouts

Pick one of these three shells. Examples use icons from `lucide-react` (`import { Bell } from 'lucide-react'`); `Logo` stands for your own logo component.

**1. Header only** — navigation in the header:

```tsx
<Header>
  <HeaderContent>
    <HeaderLeft>
      <Logo />
      <NavigationMenu>
        <NavigationMenuList>
          <NavigationMenuItem><NavigationMenuLink href="/">Home</NavigationMenuLink></NavigationMenuItem>
          <NavigationMenuItem>
            <NavigationMenuTrigger>More</NavigationMenuTrigger>
            <NavigationMenuContent><div className="grid gap-3 p-4 w-100">...</div></NavigationMenuContent>
          </NavigationMenuItem>
        </NavigationMenuList>
        <NavigationMenuIndicator />
      </NavigationMenu>
    </HeaderLeft>
    <HeaderRight>
      <Button variant="ghost" size="icon" aria-label="Notifications"><Bell className="h-4 w-4" /></Button>
      <Avatar><AvatarImage src="..." alt="User" /><AvatarFallback>U</AvatarFallback></Avatar>
    </HeaderRight>
  </HeaderContent>
</Header>
<main className="bg-background"><Content>...</Content></main>
```

**2. Header on top, sidebar below** — full-width header with branding and utilities; the sidebar sticks under it (default `Sidebar`):

```tsx
<Header>
  <HeaderContent container={false}>
    <HeaderLeft><Logo /></HeaderLeft>
    <HeaderRight>...</HeaderRight>
  </HeaderContent>
</Header>
<div className="flex">
  <Sidebar>
    <SidebarContent>
      <CollapsibleGroup title="Navigation" defaultOpen>
        <NavItem href="/" isActive>Home</NavItem>
        <NavItem href="/docs">Docs</NavItem>
      </CollapsibleGroup>
    </SidebarContent>
  </Sidebar>
  <main className="flex-1 bg-background"><Content>...</Content></main>
</div>
```

**3. Sidebar beside the header** — the sidebar spans the full viewport height and owns the branding; the header only covers the content column. Pass `fullHeight`:

```tsx
<div className="flex min-h-screen">
  <Sidebar fullHeight>
    <SidebarHeader><span className="font-semibold">App Name</span></SidebarHeader>
    <SidebarContent>
      <CollapsibleGroup title="Navigation" defaultOpen>
        <NavItem href="/" isActive>Home</NavItem>
        <NavItem href="/docs">Docs</NavItem>
      </CollapsibleGroup>
    </SidebarContent>
    <SidebarFooter><Muted>v1.0.0</Muted></SidebarFooter>
  </Sidebar>
  <div className="flex flex-1 flex-col">
    <Header>
      <HeaderContent container={false}>
        <HeaderRight>...</HeaderRight>
      </HeaderContent>
    </Header>
    <main className="flex-1 bg-background"><Content>...</Content></main>
  </div>
</div>
```

The sidebar has no built-in mobile behavior. On small screens hide it with `className="hidden lg:flex"` and render the same `NavItem`s inside a `Sheet` opened from a header button (`useIsMobile()` is available if you need the breakpoint in JS).

### Header

Sticky top bar (`h-16`, `z-50`, backdrop blur, bottom border) built by composing subcomponents. No variant props.

| Component | Description |
|---|---|
| `Header` | Root sticky `<header>` |
| `HeaderContent` | Flex row, `h-14`, `container mx-auto` by default. `container={false}` removes the max-width (use it next to a sidebar) |
| `HeaderLeft` | Left slot — branding and navigation |
| `HeaderCenter` | Center slot — search or centered controls (optional) |
| `HeaderRight` | Right slot (`ml-auto`) — actions and user controls |

Centered search: `<HeaderCenter><Searchbar className="max-w-md" /></HeaderCenter>`.
`NavigationMenuViewport` renders automatically when `viewport={true}` (default). Set `viewport={false}` to position it manually.
Custom background: `<Header className="bg-linear-to-r from-primary/90 to-secondary/90 border-transparent">`

### Sidebar

Sticky, `w-64`, `bg-surface` with a right border, `p-6`.

| Prop / component | Description |
|---|---|
| `Sidebar` `fullHeight` | `false` (default): below a full-width header — `top-16`, height `100vh - 64px`. `true`: beside the header — `top-0`, `h-screen` |
| `SidebarHeader` / `SidebarContent` / `SidebarFooter` | Top area with bottom border / scrollable middle / bottom area with top border |
| `NavItem` | Link. `isActive` → `bg-secondary text-secondary-foreground`; hover → `bg-secondary/70`. `asChild` renders a child as the anchor |
| `CollapsibleGroup` | Animated collapsible section. `title` (required), `defaultOpen` |

### Footer

Same composition model as the header. `FooterMeta` (copyright row) is a **sibling** of `FooterContent`, not a child. `container={false}` on `FooterContent` / `FooterMeta` removes the max-width.

```tsx
<Footer>
  <FooterContent>
    <FooterLeft>
      <FooterLogo><Logo /></FooterLogo>
      <FooterLeftText>Operated by CERIT-SC, ICS MUNI</FooterLeftText>
    </FooterLeft>
    <FooterRight>
      <div className="flex flex-col gap-2">
        <FooterNavHeading>Resources</FooterNavHeading>
        <FooterNavLink href="/docs">Documentation</FooterNavLink>
        <FooterNavLink href="/privacy">Privacy Policy</FooterNavLink>
      </div>
    </FooterRight>
  </FooterContent>
  <FooterMeta copyright={`© ${new Date().getFullYear()} e-INFRA CZ`} />
</Footer>
```

### Content

Always wrap page body in `Content` — do not add ad-hoc padding to `<main>`.

| Component | Element | Built-in spacing |
|---|---|---|
| `Content` | `div` | `mx-auto w-full max-w-7xl space-y-8 px-4 pt-8 pb-10 md:px-6 lg:px-8 xl:px-10` |
| `ContentHeading` | wraps `H1` | `mb-6` |
| `ContentSubheading` | wraps `H2` | `mt-12 mb-4 first:mt-0` |
| `ContentBody` | `div` | `space-y-4` |

Heading margins win over the container's `space-y-8`, so pass `className` to adjust a single heading.

```tsx
<Content>
  <ContentHeading>Page Title</ContentHeading>
  <ContentSubheading>Section</ContentSubheading>
  <ContentBody><P>Content here.</P></ContentBody>
</Content>
```

### Chat interfaces

Build chat UIs (assistants, support chat, messaging) only from the chat components — never hand-roll a scroll container, message bubbles or a composer.

```tsx
import {
  Chat, ChatHeader, ChatMessages, ChatFooter,
  MessageScrollerProvider, MessageScroller, MessageScrollerViewport,
  MessageScrollerContent, MessageScrollerItem, MessageScrollerButton,
  Message, MessageContent, MessageActions, MessageCopyButton, MessageTyping,
  Bubble, BubbleContent,
  MessageInput, MessageInputAttachments, MessageInputTextarea, MessageInputToolbar,
  MessageInputToolbarLeft, MessageInputToolbarRight, MessageInputAttachButton, MessageInputSubmit,
  Small,
} from '@e-infra/design-system'
import type { MessageInputStatus } from '@e-infra/design-system'

// status: 'ready' | 'submitted' | 'streaming' — owned by your app
<Chat>
  <ChatHeader><Small className="font-medium">Support assistant</Small></ChatHeader>
  <ChatMessages>
    <MessageScrollerProvider>
      <MessageScroller>
        <MessageScrollerViewport>
          <MessageScrollerContent busy={status === 'streaming'} className="mx-auto w-full max-w-3xl p-4">
            {messages.map((m) => (
              <MessageScrollerItem key={m.id} messageId={m.id}>
                {m.role === 'user' ? (
                  <Message align="end">
                    <MessageContent>
                      <Bubble variant="default" align="end">
                        <BubbleContent>{m.text}</BubbleContent>
                      </Bubble>
                    </MessageContent>
                  </Message>
                ) : (
                  <Message align="start">
                    <MessageContent>
                      <Bubble variant="ghost">
                        <BubbleContent className="text-base">{m.text}</BubbleContent>
                      </Bubble>
                      <MessageActions>
                        <MessageCopyButton value={m.text} />
                      </MessageActions>
                    </MessageContent>
                  </Message>
                )}
              </MessageScrollerItem>
            ))}
            {status === 'streaming' && (
              <MessageScrollerItem messageId="typing">
                <Message align="start">
                  <MessageContent>
                    <Bubble variant="ghost"><BubbleContent><MessageTyping /></BubbleContent></Bubble>
                  </MessageContent>
                </Message>
              </MessageScrollerItem>
            )}
          </MessageScrollerContent>
        </MessageScrollerViewport>
        <MessageScrollerButton />
      </MessageScroller>
    </MessageScrollerProvider>
  </ChatMessages>
  <ChatFooter>
    <MessageInput className="mx-auto max-w-3xl" status={status} onSubmit={(text, files) => send(text, files)} onStop={stop}>
      <MessageInputAttachments />
      <MessageInputTextarea placeholder="Send a message…" />
      <MessageInputToolbar>
        <MessageInputToolbarLeft><MessageInputAttachButton /></MessageInputToolbarLeft>
        <MessageInputToolbarRight><MessageInputSubmit /></MessageInputToolbarRight>
      </MessageInputToolbar>
    </MessageInput>
  </ChatFooter>
</Chat>
```

**Structure**
- Shell: `Chat` → optional `ChatHeader` → `ChatMessages` → `ChatFooter`.
- Transcript nesting is fixed: `MessageScrollerProvider` → `MessageScroller` → `MessageScrollerViewport` → `MessageScrollerContent` → one `MessageScrollerItem` per turn, with a stable `messageId`. `MessageScrollerButton` (scroll back to the latest message) goes inside `MessageScroller`, next to the viewport. The scroller follows new messages automatically.
- `useMessageScroller()` (`scrollToEnd`, `scrollToStart`) and `useMessageScrollerScrollable()` only work inside `MessageScrollerProvider`.
- Constrain `MessageScrollerContent` and `MessageInput` to the same max width (`max-w-3xl`) so the transcript and composer line up.

**Sizing**
- `Chat` is `h-dvh` by default — right for a dedicated chat route.
- Inside your own layout (header, sidebar, `Content`) pass `className="h-full"`, and make sure every ancestor has a constrained height; `h-full` inside an auto-height parent has nothing to fill. For a bounded panel use a fixed height such as `h-[32rem]`.

**Turns**
- The current user's turn: `<Message align="end">` with `<Bubble variant="default" align="end">`.
- Assistant replies come in two styles — pick one and use it for replies *and* the typing indicator:
  - **Plain text** (long or structured answers): `Bubble variant="ghost"`, `BubbleContent className="text-base"`, no avatar.
  - **Bubbles** (short exchanges, human agents): `Bubble variant="muted"` with `<MessageAvatar><Avatar><AvatarFallback>AI</AvatarFallback></Avatar></MessageAvatar>` before `MessageContent`.
- Failed message: `Bubble variant="error"`. Sender name: `MessageHeader`; meta line below: `MessageFooter`. Group consecutive turns with `MessageGroup` / `BubbleGroup`.
- `MessageActions` appears on hover of the message and follows its alignment. Extra actions use `<Button variant="ghost" size="icon-sm">` with an icon plus `<span className="sr-only">Label</span>`.
- Timestamps: `<MessageTimestamp dateTime={iso}>{clock}</MessageTimestamp>`. Bubble style → `placement="beside"` inside the `Bubble`; plain style → inside `MessageActions` with `reveal="always"`.

**Composer**
- `MessageInput` is a form. `onSubmit(text, files)` fires on Enter (Shift+Enter inserts a newline) or the submit button, then clears the field.
- Drive `status` from your request state: `submitted` while waiting, `streaming` while the reply arrives, back to `ready` when done. Sending is blocked unless `status` is `ready`; while `streaming`, `MessageInputSubmit` turns into a stop button that calls `onStop`. Pass `busy={status === 'streaming'}` to `MessageScrollerContent`.
- `MessageInputAttachButton` (`accept`, `multiple`) adds files; `MessageInputAttachments` lists them. For a controlled field use `value` + `onValueChange`.

### Anti-patterns

```tsx
// ❌ Raw hex or generic Tailwind colors — ignore dark mode and themes
<div style={{ background: '#eaebf1' }}>
<div className="bg-gray-100 text-gray-900">

// ✅ Token classes adapt to light, dark and every theme
<div className="bg-surface text-text">
```

```tsx
// ❌ Dynamic class names — Tailwind never generates them
<Badge className={`bg-${status}-100`}>

// ✅ Map to complete literal class strings
const statusClass = { success: 'bg-success-100 text-success-900', warning: 'bg-warning-100 text-warning-900' }
<Badge className={statusClass[status]}>
```

```tsx
// ❌ Reversed or skipped surfaces
<div className="bg-surface"><div className="bg-background">        {/* darker than parent */}
<main className="bg-background"><div className="bg-surface-raised"> {/* skipped bg-surface */}

// ✅ Always progress in order
<main className="bg-background">
  <div className="bg-surface">
    <div className="bg-surface-raised"> {/* popovers and modals only */}
```

```tsx
// ❌ Fixed spacing on a layout container
<section className="p-6">

// ✅ Responsive stack following the spacing token scale
<section className="p-6 md:p-8 lg:p-12">
```

```tsx
// ❌ Manual dark overrides — tokens already handle this
<div className="bg-surface dark:bg-[#191820]">
```

```tsx
// ❌ Invalid heading nesting — CardTitle already renders an <h3>
<CardTitle><H4>Title</H4></CardTitle>

// ✅
<CardTitle>Title</CardTitle>
```

### Worked example — feature section

```tsx
import {
  Badge, Button, Card, CardAction, CardDescription, CardFooter, CardHeader, CardTitle,
  H2, Lead, Separator,
} from '@e-infra/design-system'

const statusClass = {
  success: 'bg-success-100 text-success-900',
  warning: 'bg-warning-100 text-warning-900',
  info: 'bg-info-100 text-info-900',
} as const

const features = [
  { title: 'GPU Computing', description: 'High-performance GPU nodes for ML workloads.', badge: 'Available', status: 'success' },
  { title: 'JupyterHub', description: 'Managed notebooks with persistent storage.', badge: 'Beta', status: 'warning' },
  { title: 'Object Storage', description: 'S3-compatible storage for datasets.', badge: 'Coming soon', status: 'info' },
] as const

export function FeatureSection() {
  return (
    // bg-background — page canvas; responsive section rhythm and page margin
    <section className="bg-background py-8 md:py-12 lg:py-16 xl:py-24 px-4 md:px-6 lg:px-8 xl:px-16">
      <div className="mb-8 md:mb-12">
        <H2 className="text-text-heading">Platform capabilities</H2>
        <Lead className="mt-2">Everything you need to run research workloads at scale.</Lead>
      </div>

      <Separator className="mb-8 md:mb-12" />

      <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4 md:gap-6 lg:gap-8">
        {features.map((f) => (
          // Card is already bg-surface with its own padding — one step above the background
          <Card key={f.title} animation="translate">
            <CardHeader>
              <CardTitle>{f.title}</CardTitle>
              <CardAction>
                <Badge className={statusClass[f.status]}>{f.badge}</Badge>
              </CardAction>
              <CardDescription>{f.description}</CardDescription>
            </CardHeader>
            <CardFooter>
              <Button size="sm">Learn more</Button>
            </CardFooter>
          </Card>
        ))}
      </div>
    </section>
  )
}
```

### Key rules

1. Never use raw hex or generic Tailwind colors — always use token classes, written as complete literal strings.
2. Surfaces must progress in order: `bg-background` → `bg-surface` → `bg-surface-raised`. Never skip or reverse.
3. Apply spacing responsively on layout containers: `p-6 md:p-8 lg:p-12`, not a single fixed value. Don't override component padding without reason.
4. Dark mode = `.dark` class on `<html>`; themes = `data-theme` on the same element. No `dark:` overrides on token classes, ever.
5. Primary navigation belongs in either the header OR the sidebar — never both. Footer holds secondary links only.
6. Sidebar below a full-width header → `<Sidebar>`; sidebar beside the header → `<Sidebar fullHeight>`.
7. Wrap all page body content in `Content` — do not add ad-hoc padding to `<main>`.
8. Only import names from the inventory list. Anything else does not exist — compose it from primitives.
9. `setup.css` must be imported in your global CSS, right after Tailwind, before any theme CSS.
10. With a client-side router, internal links use `asChild` + the router's link component — never `href` alone (full reload) and never `<Link><Button>` (invalid nesting).
11. Only use prop values from the API cheat-sheet — never guess a `variant` or `size`.
12. Build chat UIs from `Chat` + `MessageScroller*` + `Message`/`Bubble` + `MessageInput`, in the documented nesting — never a hand-rolled scroll container or composer.
````

The version at the top of this page and in the skill's first line tells you which release the skill matches. The most common changes between releases:

- New components or subcomponents — they appear in the inventory list
- New layout props — they appear in the layout sections
- Token value changes — they appear in the color tables

To verify the skill is working after any update, open a fresh session and ask your assistant: *"Which components are available in @e-infra/design-system?"* and *"How should I structure a page with a sidebar beside the header?"* The answers should match this page.
